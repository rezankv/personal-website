## My Experience Developing a Subscription Sales Platform

This project began with a simple Telegram message. Someone reached out asking for a subscription-based website. The backend of the project was already implemented, and my responsibility was to build the entire frontend. The platform included three primary roles: Admin, Marketer, and User.

### Architecture & Project Structure

After analyzing the requirements, I decided to build a separate web application for each role to ensure clean separation, easier development, and better long-term maintainability.
To achieve this, I set up a Turborepo monorepo and created three independent Next.js applications.

### Implementation & Technologies
	-	Next.js for all three applications
	-	Turborepo for monorepo management
	-	TailwindCSS for styling
	-	shadcn/ui to speed up the UI development workflow

### Challenges

The main challenge was the lack of a technical person on the client’s side. This made coordination more difficult for them, so I supported them along the way, provided guidance, and helped ensure that everything moved forward smoothly and correctly.

### Final Outcome

The final deliverable included three fully deployed Next.js web applications, each serving a specific role within the platform:
	-	User App: Subscription purchasing and payment handling
	-	Marketer App: Managing referred users and tracking earnings
	-	Admin App: Monitoring the system and managing all users and marketers

The core system flow was built around payment processing, marketer referral management, and full administrative control over the entire ecosystem.
